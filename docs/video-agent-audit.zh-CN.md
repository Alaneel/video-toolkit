# Video Agent 本地候选审计与交付

## 范围与基线

本轮在隔离工作树开发 `2.2.0-rc.1`。远端审计基线为 `6462b920f519e98c5b882e7282b469a9244750d7`；原工作树的 `master` 为 `47c34708dd75e92967894c21deefaf6a001a7c4d`。公开版本 v2.1.0 不含本次 Agent。初始开发阶段未获线上发布授权，保持本地；2026-10-18 用户补充授权在配置与验证后发布、整理 README 和 GitHub Profile。该授权不代表许可缺口或语义评价自动通过，公开安装包仍须满足独立分发门槛。

原工程不是空壳：Rust workspace、egui、CLI、FFmpeg/ffprobe 检查、MP4 格式策略和旧剪辑功能均可复用。但旧剪辑接口不提供取消、任务持久化、精确计划确认和安全发布输出，且存在覆盖参数。因此新增窄边界的 Rust `video_agent` crate，只补编排、类型校验、受限执行和恢复，不另建媒体引擎或通用 Agent 平台。

## 实现边界

- 独立原生桌面入口，仍保留旧桌面和 CLI。单视频优先，默认支持三个输入。
- 本地探测、源文件指纹、时间码抽帧；模型只能要求补充观察或提出计划，不能确认、导出、指定路径或执行 shell。
- OpenAI Responses 是唯一真实供应商适配器。模型、提示和实际观察可追溯；实际返回模型与配置模型分别记录。
- 明确同意后仅发 JPEG、意图、源 ID、时间码、尺寸及受限补充抽帧，不发原片、音频或原片路径。意图与画面仍可能有隐私，任务目录必须留在本地并按敏感数据管理。
- 人工播放、边界调整、删除、排序和添加人工片段；保存后重新确认精确 digest，旧确认失效。
- H.264/MP4 640×360/30 fps 真实导出，保留首条音轨并转 AAC/48 kHz 双声道，缺音源填静音；可选择完全无音轨。不宣称无损或源质量保留。
- 原子持久化、互斥、写前记录、禁止覆盖、输出全流解码验证。恢复到阶段或已完成分片，不是任意编码位置。
- 可取消、限时、调用/帧/令牌/估算费用预算；失败请求使用未知时保留预算，不自动重试。费用不是账单，也不是供应商硬消费上限。

后续复核补上独立、原子同步的 `execution-ledger.json`：有界的哈希、媒体及模型步骤开始前预留本步骤上界，正常结束按实测毫秒结算；进程异常结束后，下一持锁进程将遗留上界保守扣除一次，不将未知耗时清零。界面区分实测耗时、已计入的崩溃保守扣除及尚在进行的预留。重新打开时的源/输出检查也计预算；预算耗尽仍可查看保存记录，但不授予新鲜的指纹验证、成片播放或继续处理权限。旧任务从已保存计数迁移，历史未记耗时不可追溯；启用账本后缺失或非法账本会拒绝继续，不能再次当成旧任务迁移。首次检查中断留下无有效 task.json 的未完成目录，不冒充检查成功。

这属于保守记账与新工作准入控制，不是操作系统级 CPU/墙钟配额。文件系统停顿、调度和 watchdog 轮询仍有开销；若仅强杀应用，已启动的 FFmpeg 可能在其 watchdog 消失后继续运行，不能承诺孤儿进程的墙钟停止时刻。真实进程组硬杀测试验证一次性预算结算；另有真实生产导出 owner-only 硬杀测试，在完成首个分片后只杀应用进程，由测试脚本明确清理可能的孤儿媒体进程，再经第二进程恢复并检查分片复用与唯一成片。两者均不冒充断电测试或真实模型验证。

后续已将 `max_concurrency` 实际接入初始及补充 JPEG 抽取，桌面可配置1–4路，CLI 创建任务可用 `--frame-workers`（别名 `--max-concurrency`）。它不是云模型并发、多个Agent任务或FFmpeg编码线程数；云请求、源校验、确认与导出仍顺序执行。每批共享一个绝对 deadline 与持久预留，单一 owner 持任务锁、按请求顺序校验实际PTS并先记账再发布；取消/首错会回收并等待全部worker，失败批不发布不完整观测，之前成功批可恢复。

界面的 Frame credits 是已记账的唯一观测记录与人工预览尝试额度，不是所有失败decode次数，也不保证等于已有JPEG数量。观测元数据先于图片发布记账，中断后须重建并校验缺图；人工预览在抽取前扣额度，失败/取消可能仍保留扣账。实际模型可见证据以分镜列表及每次请求保存的sample IDs为准，不能由额度反推。重算仍消耗执行预算。界面另示已记录worker峰值与返回worker墙钟时长之和，后者不是CPU时间，也不重复计入执行预算。模型请求在本地准入阶段停止、尚未进入供应商时会标 `not_sent`，退还令牌/费用预留但保留本地尝试次数；已发送且账单未知的请求仍保守保留预算。

## 真实性分层

| 证据 | 可支持 | 不能支持 |
| --- | --- | --- |
| 类型/流程测试与模拟供应商 | 参数边界、确认、恢复、预算、非法工具拒绝 | 模型实际理解画面 |
| 真实 FFmpeg/ffprobe/音频检查 | 文件可解码、时长、流与音轨策略 | 片段语义相关性 |
| 原生 GUI 手动闭环 | 界面可操作、人工编辑与本地导出 | 真实 AI 选片演示 |

2026-10-18 用户自行完成本机凭据填写，应用重新载入显示 configured，执行者没有读取密钥内容。旧模型首个真实 Responses 调用报告5412输入/144输出令牌、4958毫秒，预估费用0.0023952美元（不是账单）；18.75秒单段超过15秒上限被拒，后续两次失败同样保留。用户同意迁移后，Luna真实运行4次：两次主动补充观察、一次越界引用被拒、一次结构合法草案，共30004输入/1222输出令牌，预估0.0043615美元。任务保存35张观测，实际每次发送12/24/16/16张，历史并集28张，不能把35张都说成模型已经看过。v4仅改变单次上下文为最多16张，保留全部本地观测、原调用/令牌/费用上限及每请求引用约束，不做语义排序。

Luna合法草案为5段25秒，首段洞口没有清晰兔子，模型自己也注明；执行者已请求真人决定是否删除该段得到20秒。当前未代替用户回答、未确认或导出该草案。所有原始任务、账本、首次及后续只读capture保留在仓库外，仅公开脱敏计数/ID/时码摘要与原生截图。正式真人语义比较、heldout与基线评价和完整连续录屏仍待完成，不得由结构校验或成片可播放推断通过。heldout未用于此次调试。

旧默认 `gpt-4.1-mini-2025-04-14` 已被官方列入弃用，2027-01-14 停用。它在v1/v2/v3提示上的三次开发提案均未通过本地校验，费用与失败全部保留；2026-10-18 用户明确同意切换到 `gpt-6-luna` 继续验证。Luna显式使用Responses、low reasoning与standard tier，保留原输出/调用/费用/时长上限，不将旧快照的图像计费规则冒充新模型规则。首次Luna真实调用主动请求补看12张，生成后因原4096/图的预留过于保守，下一请求被100k令牌预算拦住，该停止也保留。后续将内建估算限定到产品实际<=640×360缩略图、每张2048 token；更大图必须显式配置更高预留，仍不声称官方精确公式或硬费用保证。真实报告超预留则保留用量并拒收。旧配置兼容但仍显示弃用警告。新模型验证状态由实际运行记录决定。[旧模型通知](https://developers.openai.com/api/docs/deprecations#2026-10-14-gpt-4-series-model-deprecations)、[Luna能力](https://developers.openai.com/api/docs/models/gpt-6-luna)、[当前价格](https://developers.openai.com/api/docs/pricing)。

## 交付证据与发布闸门

本地测试统计、实际界面截图、手动导出文件、取消恢复在 [候选证据记录](video-agent-evidence.json) 中逐项列明。真实 GUI 完成12张抽帧、人工预览/裁剪/增加/删除/重排、保存 revision 2、绑定 digest 确认、导出中取消并继续；重新启动独立应用后打开同任务，实际 QuickTime 播放成功。该 GUI 运行在首个分片完成前取消，因此只能证明保留阶段恢复；已有分片复用由独立真实编码取消测试证明。视频27.000秒，AAC padding使容器27.021333秒，均不是语义质量证据。25秒界面短片由真实静态截图组成，不伪称连续录屏；完整真实模型演示仍待补。

补充走查使用已解包的 `4c05e71` 原生 app，导入同一合法开发影片的有声源和无声派生文件，在 GUI 生成12张时间码样本、额外本地预览，加入/裁剪并跨源重排，保存 revision 2 后确认并导出8秒视频，重新加载、复验并在 QuickTime 实际播放。独立审阅核对了原片/样本/分片/成片哈希、计划 digest、唯一输出与复用事件，并对实际画面顺序做正确源/错误源 SSIM 对照；前段音量为 −91.0 dB，后段 −37.8 dB，符合静音→有声。该证据不验证稍后新增的预算代码，不是多种实拍场景泛化或真实模型评分；新代码的验证另外列明。
